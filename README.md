> **本引擎从代码到完成，全部由豆包 AI 制作；内容架构与世界观设定由作者提供。**
> 使用中遇到任何问题、想改设定或加功能，直接去找豆包反馈就行，不用自己啃代码。

给 DSH 装上一条**会自己活着的时间线**：一个持续自演化的文字世界，接在 DSH 设置页里，随时看得见世界时间、她在想什么、今天发生了什么。

引擎本体随插件包一起交付，装上插件即自动拉起、看门狗托管、崩溃自动重启——不需要再单独装引擎、配守护脚本或加开机自启。

---

## 它是什么

「世界引擎」是一个**故障隔离的独立 Node 子进程**，负责时序推进、主角状态、时间线、快照、记忆桥、低速自演化与审批链路；DSH 插件只做两件事：宿主半边的安全代理与进程托管，网页半边的设置页面板。

- **世界自己在走**：按现实时间推进世界时钟（星期 / 时段 / 季节），每天若干次自演化节拍，生成日常事件与 NPC 自主行为。
- **重大节点必须审批**：会改变世界线的节点先推送到审批链路，同意后才写入世界线；这是法则锁定项，面板不提供关闭开关。
- **她有自己的状态**：心情、疲劳、思念、思绪，随事件与时间变化。
- **代码与存档严格分离**：升级/重装插件绝不动你的存档。

### 它不依附任何其它插件

- **不是 SurfCore 的附属品**：这是一个独立的 DSH 插件（`dsh.bundle` + 可选 `dsh.client` 面板），`lib/host.js` 只用 Node 标准库，`engine/` 零第三方依赖。任何装了 DSH 0.2.1+ 的环境，装上它就能跑，不需要先装 SurfCore 或别的插件。
- SurfCore 只留一处**可选**痕迹：审批链路想联动 QQ 私聊时，引擎会去读 `F:\DSH-Data\surfcore\config.json` 取 OneBot 端点（可用 `WORLD_ENGINE_SURFCORE_CONFIG` 覆盖），读不到就用回退值、审批回到面板里点。不装 SurfCore 只影响这一条可选链路。早期挂在 SurfCore 控制台的入口已经移除。
- **世界包格式是本插件自己的约定**，不是 DSH 通用标准：别的插件读不了你的世界包，它也不会去读别的插件的资源。换的是题材，不是格式。

下面这套是作者本机每天在跑的，也是本插件唯一验证过的搭配：

## 架构

```
DSH 宿主进程（Electron）
└─ 插件 dsh-world-engine
   ├─ lib/host.js      宿主半边：引擎子进程托管 + 看门狗 + 路由代理 + 聚合状态
   ├─ engine/          随包引擎本体（纯 Node 标准库，零第三方依赖）
   └─ lib/client.js    网页半边：DSH 设置页 settings.section 面板
```

| 半边 | 文件 | 职责 |
| --- | --- | --- |
| 宿主 host | `lib/host.js` | 拉起并托管引擎子进程（5 秒健康巡检 + 冷却防重启风暴）；注册 `/dsh-world-engine/*` 路由：回环/同源门控后代理到本机引擎；`/state` 聚合路由一次拉齐面板所需状态 |
| 引擎子进程 | `engine/` | 时序、状态、时间线、快照、记忆桥、自演化调度、审批 WS、HTTP 接口 |
| 网页 client | `lib/client.js` | 设置页面板；纯 `createElement`，无 JSX 无构建；只调宿主路由，不直连引擎端口 |

**为什么故障隔离**：引擎崩了不拖垮宿主。看门狗检测到 `/api/status` 不通且过了冷却期就重拉子进程，面板显示 PID / 重启次数 / 端口 / 数据根。

## 面板功能

DSH 设置左侧栏的「世界引擎」面板，其中「功能说明」卡片在页面顶部逐条写明了每个区块的用途与边界。

- **世界概览** — 世界名、主角与称呼、世界时间、位置、心情、疲劳/思念、思绪、时间线与记忆条数、审批链路状态、托管进程状态。
- **演化规则** — 演化总开关、随机日常、NPC 自主、主动搭话、共享世界；每日节拍、事件冷却、事件密度。
- **重大节点审批** — 待审批预案列表，同意 / 拒绝。
- **NPC 管理** — 自主总开关；逐个 NPC 启用停用与频率。
- **地点管理** — 地点名称、氛围描写、地点回忆；启用 / 仅背景标记；新增与删除。
- **记忆** — 预置共同回忆增删改（文案、重要程度、距今天数、标签）；运行时向量记忆检索与全量导出。
- **近期事件** — 时间线最近事件（类型标签 + 时间 + 文案）。
- **数据维护** — 立即完整备份、按快照回滚、两档重置（清空演化状态 / 全量重置，二次确认，重置前自动快照）。

## 安装

> 想让角色出现在屏幕上、或者没人说话时自己起个话头，可以叠加桌宠与主动搭话类插件（`feiyu-chat-companion` / `dsh-pet` / `dsh-speak-up`）。装什么、放哪里、哪些能联动，见 [`docs/制作自己的世界包.md`](docs/制作自己的世界包.md) 第 9 节「装什么、放哪里：搭配清单」。

### 方式一：本地链接（开发版）

1. 把包目录放到本机插件目录；
2. profile `package.json` 依赖加 `"dsh-world-engine": "link:<包目录绝对路径>"`，`dsh.profile.bundles` 追加 `dsh-world-engine`；
3. `node_modules` 下建到包目录的 junction；
4. 重启 DSH，设置页左侧出现「世界引擎」。

### 方式二：插件市场

包内已带 `dshhub` 清单（`package.json` 的 `dshhub` 段）：`schemaVersion 1`、surfaces `host` + `web`、网络权限仅声明回环地址。按市场规范发布后可从插件市场安装与升级。

## 配置

全部走环境变量，缺省值适配单机常用布局：

| 变量 | 默认 / 取值 | 作用 |
| --- | --- | --- |
| `WORLD_ENGINE_URL` | `http://127.0.0.1:32100` | 宿主代理目标地址 |
| `WORLD_ENGINE_PORT` | `32100` | 引擎子进程监听端口 |
| `WORLD_ENGINE_DATA` | 未设则沿用已存在的存档数据根，否则落到 `$DSH_HOME/world-engine-data` | 存档目录；已有存档一律沿用，绝不重建 |
| `WORLD_ENGINE_NODE` | 未设则用宿主进程自身可执行文件（Electron 下子进程带 `ELECTRON_RUN_AS_NODE=1` 当纯 Node 跑） | 引擎子进程用的 Node |
| `WORLD_ENGINE_SURFCORE_CONFIG` / `WORLD_ENGINE_SNOWLUMA_HOME` | 覆盖默认桥接路径 | 审批链路桥接配置 |

## 世界观从哪里来

世界名 / 副标题 / 口吻 / 预置回忆 / NPC / 地点 / 事件池都来自**世界包**：

- 模板在 `engine/packs/<包名>/config/*.json`；
- 首次初始化时复制到存档目录 `worlds/<包名>/config/`，之后面板改动都保存在存档副本；
- 当前启用哪个包由存档根 `active.json` 决定；面板编辑不会回写模板。

内置一个示例包 `packs/sao`。换世界包：在 `engine/packs/` 放新包并切换当前包即可。

**想搭自己的世界？** 看 [做一个你自己的世界](./docs/制作自己的世界包.md) —— 面向不懂代码的人，讲清六个文件各管什么、字段怎么说人话、怎么激活、怎么验证，末尾还附了可以直接发给 AI 的一整段需求描述。

## 更新

- **本机开发版**：profile 用 `link:` 本地链接时市场不做 registry 更新比对，改源码后重启 DSH 即生效，`package.json` 的 `version` 随迭代上提。
- **市场安装版**：按版本号检测更新，在插件市场面板升级。引擎代码随插件包一起更新，不需要单独维护引擎。

## 不做的事

- 不在面板开放法则层字段（时间倍率、数据目录、原作男主策略、羁绊归属、审批锁定）。
- 不做遗忘权重；记忆分区标签与适配器接口预留，向量库沿用现有文件记忆库。
- 运行时向量记忆只追加，面板仅提供检索与导出（引擎暂无逐条改写接口）。
